# Directory Structure

```text
/
├── CLAUDE.md                    # Master configuration
├── .claude/                     # Agent definitions, skills, hooks, rules, docs
├── design/                      # Game design documents (gdd, narrative, levels, balance)
├── docs/                        # Technical documentation (architecture, api, postmortems)
│   └── engine-reference/        # Curated engine API snapshots (version-pinned)
├── production/                  # Production management (sprints, milestones, releases)
│   ├── session-state/           # Ephemeral session state (active.md — gitignored)
│   └── session-logs/            # Session audit trail (gitignored)
└── game/                        # Godot project root (project.godot added here at dev start)
    ├── src/                     # Game source code (core, gameplay, ai, networking, ui, tools)
    ├── assets/                  # Game assets (art, audio, vfx, shaders, data)
    ├── tests/                   # Test suites (unit, integration, performance, playtest)
    ├── prototypes/              # Throwaway prototypes — gitignored, safe to delete
    │   └── previews/            # Wireframe .tscn scenes generated by /preview-scene
    └── tools/                   # Build and pipeline tools (ci, build, asset-pipeline)
```

## Rationale — `game/` as Godot project root

The Godot project (`project.godot`) lives inside `game/` rather than at the repo root.
This keeps the engine's file-system scanner isolated to game files only — Godot never
sees `design/`, `docs/`, or `production/`. No `.gdignore` files needed; clean separation
between studio management layer (repo root) and game code (inside `game/`).

When starting development: run `/setup-engine` from inside `game/` to initialise
`project.godot`. The Godot editor's FileSystem dock will show only `game/` contents.
