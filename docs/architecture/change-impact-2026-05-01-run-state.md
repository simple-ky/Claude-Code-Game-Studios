## Impact Analysis

### ADR-0001: Run State / Game Flow — Status: 🔴 Likely Superseded (handled in-place)

**What the ADR assumed**:
- 13 consumer GDDs (including Wave Summary UI #32).
- `pause()` / `resume()` return `void`.
- No `quit_run()` API method; quit handled by transitioning to `RUN_RESULTS` from RUN_PAUSED only.
- Snapshot Dictionary is fixed at 9 keys; ADR-0006 owns the on-disk policy.
- `previous_state` typed as `int`, sentinel value bare `-1`.
- External pause sources detected by polling `get_tree().paused` in `_process()`.
- Formulas call `Time.get_unix_time_from_system()` directly.
- F3's wave-display rule has no helper method (consumer-side reimplementation expected).
- No `state_loaded` signal; `state_changed` fires for both transitions and load-restoration.

**What the GDD now says (R2+R3)**:
- 12 consumer GDDs (#32 deleted — replaced by HUD #29 toast + Tab-toggle summary).
- `pause()` / `resume()` return `bool` (T12).
- New public `quit_run(outcome: int) -> bool` API method, callable from any in-run state (T1+T7).
- Snapshot Dictionary retains its shape; runtime fields `phase_entered_at`, `phase_pause_started_at`, `total_paused_seconds` added (T2+T13). Per R3, no on-disk policy is required (suspend-save removed).
- `previous_state: int` with named class constant `STATE_NONE = -1` (T16).
- External pause via `_notification(NOTIFICATION_APPLICATION_FOCUS_OUT/IN)` (T14) — fires for Steam overlay, Alt-Tab, window minimize uniformly. Polling rejected as technically broken.
- All formulas route through `_get_unix_time()` virtual hook (T19); direct `Time.get_unix_time_from_system()` calls FORBIDDEN.
- New public helper `get_displayed_wave_number(state_override: int = current_state) -> int` (T3).
- New `state_loaded(snapshot)` signal emitted by `load_snapshot()` (T17).
- Plus T4 (MAIN_MENU resets run-context), T5 (queued wave-complete on pause), T6 (outcome priority VICTORY > DEFEAT > QUIT), T8 (`wave_ended` before `run_ended(DEFEAT)` + defeat-path `current_wave++`), T9 (`card_picked.emit()` gated), T10 (load-snapshot validation rules), T11 (`load_snapshot()` API + code-review-checklist rule with R3 test-injection exemption), T15 (locked quit-from-CARD_ROLL confirmation text), T18 (optional MVP-deferred polish).

**Assessment**:
ADR-0001 is in `Proposed` status, so this is "tightening before lock" rather than supersession in the strict sense. But the contract surface is materially different — 6 new methods, 1 new signal, 2 new fields, 1 new constant, plus behavioural changes. A separate superseding ADR is not warranted because all changes are additive or refinements; the architectural choice (autoload + flat enum + signal-based) is unchanged.

**Resolution**: **Update in place**. Applied 2026-05-01:
- New "Tightenings (R2+R3, applied 2026-05-01)" section added between Architecture Diagram and Alternatives Considered, capturing T1-T19 with cross-references back to GDD sources.
- Key Interfaces section expanded with all new methods, signals, fields, and constants.
- Status field updated; Revision History added.
- Enables/Blocks reduced from 13 → 12 consumer GDDs.
- Risk 5 closed (Steam overlay properly detected via focus notifications) with residual `low_processor_mode` concern noted.
- Migration Plan §1 expanded with 6 new pre-implementation verifications (T14 focus signal, T16 enum coercion, T19 clock injection, E9 low_processor_mode, D12 gamepad, T6 outcome priority).
- Validation Criteria expanded with per-tightening verification table (T1-T19).
- GDD Requirements Addressed table marks Wave Summary UI #32 as DELETED with strikethrough.

### ADR-0006: Save Schema & Versioning — Status: ⚠️ Needs Review (handled in-place)

**What the ADR assumed**:
- 8 persistent domains, including `run_snapshot.save` (ADR-0001's snapshot persisted via `SaveManager`).
- `CURRENT_SCHEMA_VERSIONS["run_snapshot"] = 1`, with the `schema_version` value MUST equal ADR-0001's snapshot schema_version.
- ADR-0001 → ADR-0006 dependency is hard (this ADR persists ADR-0001's snapshot).
- One concrete schema bump (v1→v2) was planned for `run_snapshot` per R2's tightenings T20 (snapshot expansion with `phase_entered_at`/`phase_pause_started_at`/`meta_progress_events_fired`) — would be the validation exemplar of the schema-bump procedure.

**What the GDD now says (R3)**:
- Suspend-save mechanism REMOVED entirely. The run is a single session — no mid-run resume.
- Save/Load #2 demoted from Hard to Soft consumer of Run State; persists meta-currency, achievements, unlocks, and settings only (NOT run-state).
- Run State's `_build_snapshot()` Dictionary is runtime-only (used by Test Harness assertion + the `state_snapshot_ready` signal); never written to disk.
- T20-T22 deleted along with the suspend-save mechanism.

**Assessment**:
ADR-0006's other contracts (envelope format, atomicity rules, `.bak` chain, `FileAccess.store_*` return-checking, Windows remove-before-rename) are unaffected and remain authoritative. Only the `run_snapshot.save` domain assumption is dead. The ADR-0001 → ADR-0006 dependency is now LIGHT — the enum-stability + JSON-serializable rules still inform this ADR, but there is no `schema_version` coupling.

**Resolution**: **Update in place**. Applied 2026-05-01:
- Status field + Revision History note added.
- Depends On / Enables / Ordering Note: dependency on ADR-0001 marked LIGHT.
- Problem Statement: 8 persistent systems → 7. ADR-0001 hand-off paragraph rewritten (no on-disk policy required for the run snapshot).
- Constraints: ADR-0001 inheritance rule rewritten as a general format rule (not a run-snapshot-specific rule).
- File Layout: `run_snapshot.save` row marked DELETED with strikethrough + R3 rationale.
- Format Specification: paragraph about run_snapshot's `data` field rewritten to note the deletion.
- Key Interfaces: `CURRENT_SCHEMA_VERSIONS` no longer includes `run_snapshot`; explanatory comment added.
- GDD Requirements Addressed: ADR-0001 row updated to reflect the run-snapshot deletion.
- Validation Criteria: schema-bump exemplar moved from `run_snapshot` to a synthetic Test Harness fixture domain.
- Related Decisions: ADR-0001 entry rewritten to note the post-R3 light dependency.
- Risk 3 (`inserting_game_state_enum_values`): preserved as a generalised project-wide rule for any persisted enum (e.g. `RunOutcome` in leaderboard records), but no longer driven by GameState specifically.

### ADR-0002 / ADR-0003 / ADR-0004 — Status: ✅ Not Affected

- **ADR-0002 (Crowd Pathfinding)**: Pathfinding is regenerated each wave, never persisted. The R2/R3 changes to Run State's pause semantics, save model, and consumer count do not touch the pathfinding contract.
- **ADR-0003 (Language Routing Policy)**: The Wave System (C#) → Run State (GDScript) signal contract is unchanged. `WaveCompleteEventHandler` still fires once per wave end via typed Callable. The R2 tightening T8 (`wave_ended` before `run_ended(DEFEAT)`) is a *handler ordering* rule for Wave System's GDD, not a language-routing change.
- **ADR-0004 (Juice Pipeline)**: Juice owns no persisted state and no Run State signal subscriptions are added. The pause/resume signal contract was already documented as compatible.

**Resolution**: **Keep as-is**. No edits required.
