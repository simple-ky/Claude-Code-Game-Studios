# Testing Standards

What gets tested, how, and what evidence each story type requires.

> Source: `.claude/docs/coding-standards.md` (Testing Standards section).

---

## Required test evidence by story type

Every story has a **type** that determines its required evidence:

| Story type | Required evidence | Location | Gate |
|------------|-------------------|----------|------|
| **Logic** (formulas, AI, state machines) | Automated unit test (must pass) | `tests/unit/<system>/` | BLOCKING |
| **Integration** (multi-system) | Integration test or playtest | `tests/integration/<system>/` | BLOCKING |
| **Visual / Feel** (animation, VFX, feel) | Screenshot + lead sign-off | `production/qa/evidence/` | ADVISORY |
| **UI** (menus, HUD, screens) | Manual walkthrough doc / interaction test | `production/qa/evidence/` | ADVISORY |
| **Config / Data** (balance tuning) | Smoke check pass | `production/qa/smoke-<date>.md` | ADVISORY |

`/story-done` enforces this: BLOCKING gates prevent closure; ADVISORY gates warn.

## Automated test rules

### Naming

- **Files:** `[system]_[feature]_test.[ext]`
  - Example: `combat_damage_formula_test.gd`, `inventory_capacity_test.cs`
- **Functions:** `test_[scenario]_[expected]`
  - Example: `test_zero_damage_still_triggers_on_hit_effects`

### Determinism

> Tests must produce the same result every run.

- **No random seeds.** If randomness is needed, inject a seed.
- **No time-dependent assertions.** Don't compare against `Time.now()`.
- **No execution order dependencies.** Each test sets up and tears down its own state.

### Isolation

- **No external API calls.** Mock or stub.
- **No real database/filesystem.** Use in-memory or fixtures.
- **Dependency injection.** Don't pull from singletons.

### No hardcoded magic data

Use **constant files** or **factory functions**:

```gdscript
# GOOD
const TEST_WEAPON = preload("res://tests/fixtures/weapons/sword.tres")

func test_damage_calculation() -> void:
    var dmg = calculate_damage(TEST_WEAPON, 10)
    assert_eq(dmg, 15)

# BAD — magic numbers
func test_damage_calculation() -> void:
    var dmg = calculate_damage(some_weapon, 10)
    assert_eq(dmg, 15)  # Why 15? What's `some_weapon`?
```

**Exception:** Boundary-value tests where the exact number IS the point (e.g. "when armor = 999, damage clamps to 1").

## What NOT to automate

Some things are better tested manually:

| Skip automating | Test manually |
|-----------------|---------------|
| Visual fidelity (shader output, VFX appearance) | Screenshot + designer review |
| "Feel" qualities (input responsiveness, weight) | Playtest |
| Platform-specific rendering | On-target hardware |
| Full gameplay sessions | Playtesting |

`/test-evidence-review` distinguishes between testable-but-skipped (a problem) and not-testable-by-design (fine).

## Engine-specific test runners

### Godot (this project)

- **GDScript:** GUT (Godot Unit Test)
- **C#:** GodotXUnit or chickensoft-games/GoDotTest (finalize on first sprint)
- **CI command:** `godot --headless --script tests/gdunit4_runner.gd`

### Unity

- **Test Runner** (built into Unity Editor)
- **CI:** `game-ci/unity-test-runner@v4` (GitHub Actions)

### Unreal

- **Automation Framework** (built into UE5)
- **CI:** Headless runner with `-nullrhi` flag

## CI/CD rules

- Automated tests run on every push to main and every PR
- **No merge if tests fail.** Tests are blocking gates.
- **Never disable / skip failing tests** to make CI pass — fix the underlying issue
- **Quarantine flaky tests** with `/test-flakiness`. Don't ignore, don't delete.

## Manual evidence standards

For ADVISORY gates (Visual / UI / Config), evidence goes in `production/qa/evidence/`:

### Screenshots

- File name: `<story-id>-<aspect>-<date>.png`
- Resolution: target resolution at minimum (1920×1080 for PC)
- Annotation: pixel ruler or text overlay if comparing to a spec

### Manual walkthrough docs

- File name: `<story-id>-walkthrough-<date>.md`
- Required sections: Steps Performed, Expected vs Actual, Screenshots, Sign-off

### Smoke check reports

- File name: `production/qa/smoke-<date>.md`
- Generated by `/smoke-check`

## Common pitfalls

- **Logic stories without tests.** `/story-done` blocks closure. Always.
- **Integration stories with only a unit test.** Doesn't satisfy the gate. You need an integration test or a documented playtest.
- **Flaky tests left running.** Erodes CI confidence. Quarantine or fix.
- **Tests that mock the database when integration tests should hit a real one.** Mock too aggressively and you miss real bugs.

## Anatomy in practice

### Logic test (GDScript with GUT)

```gdscript
extends GutTest

const DamageService = preload("res://src/gameplay/combat/damage_service.gd")


func test_zero_armor_damage_equals_base() -> void:
    var service = DamageService.new()
    var result = service.calculate_damage(10, 0, false, 0.5)
    assert_eq(result, 10)


func test_armor_reduces_damage_to_at_least_one() -> void:
    var service = DamageService.new()
    var result = service.calculate_damage(10, 999, false, 0.5)
    assert_eq(result, 1)


func test_crit_doubles_damage() -> void:
    var service = DamageService.new()
    var no_crit = service.calculate_damage(10, 0, false, 0.5)
    var crit = service.calculate_damage(10, 0, true, 0.5)
    assert_eq(crit, no_crit * 2)
```

### Integration test (multi-system)

Verifies that an attack registers, damage calculates, on-hit effects fire, and the display updates — all together. Stub out non-essential systems; assert the integration points.
